# 시안 비교와 선택 기록

## 비교 페이지 구성

프로젝트의 기존 시안 폴더를 확인하고, 없으면 design-proposals 아래에 작업별 폴더를 만든다. 비교 페이지는 index.html로 제공한다. 아래는 내용 구성 기준이며 고정된 시각 스타일은 아니다.

| 영역 | 포함할 내용 |
|---|---|
| 작업 목표 | 개선할 업무와 대표 화면 |
| 현재 상태 | 현재 화면의 문제와 유지할 장점. 이미지 사용 시 식별정보 제거 |
| 안별 비교 | 이름, 정보 배치의 차이, 장점, 한계, 적용 부담 |
| 추천 | 추천안 하나와 해당 앱에 적합한 이유 |
| 시안 열기 | 각 안을 직접 열 수 있는 상대 경로 링크 |
| 체험 업무 | 같은 데이터를 이용하는 대표 업무 2~3개 |
| 선택 | 한 안 선택, 부분 조합, 수정 요청을 전달하는 방법 |
| 시연 범위 | 실제 저장·전송과 연결되지 않은 동작, 외부 리소스 의존 여부 |

처음 보는 사람도 대표 업무를 수행할 수 있게 하되, 디자인 시안 자체에 기술 설명을 과도하게 넣지 않는다. 비교 설명은 비교 페이지에서 제공한다.

## 비교가 유효한 조건

- 두 안의 데이터·필드·지표 정의와 기능 범위가 같아야 한다.
- 색상만 바꾼 안을 독립된 디자인 방향으로 포장하지 않는다.
- 최종 구현이 어려운 효과로 시안을 유리하게 보이게 하지 않는다.
- 한 안만 추천하는 경우에도 사용자가 수정하거나 유지안을 선택할 수 있다.
- 업무용 앱은 읽기·입력·탐색 효율로 평가하고, 카드 수나 애니메이션 수로 품질을 판단하지 않는다.

## 선택 기록

시안을 제공할 때 해당 작업 폴더에 decision.md를 만들고 확인된 정보만 기록한다. 승인 전에는 상태를 “선택 대기”, 선택안은 “미선택”, 실제 앱 적용 요청은 “아직 없음”으로 명시한다. 이 상태들은 템플릿의 미완성 문구가 아니라 현재 작업 상태다.

기록할 항목:

- 작업 목표와 대상 화면
- 제공한 시안의 상대 경로와 버전
- 각 안의 차이와 추천 이유
- 현재 상태: 선택 대기 / 시안 수정 중 / 적용 승인 / 적용 완료
- 사용자가 선택한 안과 요청한 조합·수정
- 실제 앱 적용 요청의 내용과 확인 시점
- 적용 범위와 별도 논의가 필요한 변경
- 수행한 화면·기능 검증 및 미확인 사항

사용자의 실제 요청 없이 승인 상태를 기록하지 않는다. 선택 기록은 재개 시 참고 자료이며, 최신 사용자 요청이 우선한다. 시안 버튼의 로컬 선택 상태만으로 적용 승인을 추정하지 않는다.

## 화면 검토

실제 앱의 주 사용 기기와 모바일에서 다음을 직접 확인한다.

- 글자·긴 이름·버튼·범례가 겹치거나 잘리지 않는가?
- 키보드 포커스와 입력 레이블이 있고, 색상 외에도 상태가 구분되는가?
- 숫자 단위와 그래프 기준이 명확하고 막대·선이 실제로 렌더링되는가?
- 검색·필터·상세 열기 같은 시연 동작이 작동하는가?
- 빈 데이터와 입력 오류를 이해할 수 있는가?
- 저장·삭제·전송이 운영 시스템을 변경하지 않는가?

브라우저 실행이 불가능하면 이를 명시하고 코드 점검만으로 화면 검수 통과를 주장하지 않는다. 캡처를 보관한다면 합성 데이터 화면만 사용한다.
